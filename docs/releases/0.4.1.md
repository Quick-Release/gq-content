# 0.4.1: a cheap check for published forms

Release `@getquick/content` and `getquick/gq-content` together from one retained
`v0.4.1` candidate. The prior stable pair was 0.4.0. The npm package's code is
unchanged; it is released with the CMS to keep the pair. No publication-store or
consent migration is added.

- **CMS:** `GetQuick\Content\Forms\published(int $form_id): bool` says whether a
  published, unprotected entry references the form, directly or through nested
  synced patterns. It is false while Gravity Forms is inactive. It reads one
  stored set of form ids and runs no query once that set is read. Saving or
  deleting a page, post, published item or synced pattern rotates a generation
  token, so the next call reads the set from content again. A read that raced
  with a save is stored under its old generation and isn't trusted.

gq-site 0.24.1's CMS gate lets anonymous requests through only to Gravity Forms'
`POST /gf/v2/forms/<id>/submissions`, for any active form. With this release a
Site's gate can also require `published($id)`, so a submission to a form no
published page shows is refused before Gravity Forms runs.

## Release gates and rollout

The required PR checks and the retained paired validation workflow must pass.
P2 adds checks for `published()`: forms shown directly and through nested synced
patterns, a form only a protected entry shows, unpublishing and publishing an
entry, editing a synced pattern, a set stored under an old generation, and no
query once the set is read. Publish only from the successful CI record, as in
[releasing](../releasing.md).
