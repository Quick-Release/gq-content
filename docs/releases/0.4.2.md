# 0.4.2: client IP behind a Site's own proxy, neutral consent HTML

Release `@getquick/content` and `getquick/gq-content` together from one retained
`v0.4.2` candidate. The prior stable pair was 0.4.1. The CMS plugin's code is
unchanged; it is released with the Frontend package to keep the pair. No
publication-store or consent migration is added.

- **`@getquick/content/forms/server`, `/consent/server`:** `createFormsServer`
  and `createConsentServer` take an opt-in `trustedProxies?: readonly string[]`
  (IPv4/IPv6 addresses or CIDRs). Only when `CF-Connecting-IP` is one of them is
  the client the right-most `X-Forwarded-For` entry that isn't a trusted proxy,
  else `X-Real-IP`; forwarding headers from anyone else are ignored. Without it,
  behaviour is unchanged. See [client IP](../client-ip.md) (#54).
- **Rate-limit keys:** `FORMS_RATE_LIMITER` and `CONSENT_RATE_LIMITER` key an
  IPv6 client by its /64 (`2001:db8:1:2::/64`), with or without proxies. IPv4
  keys are unchanged; Turnstile's `remoteip` is the full address.
- **`@getquick/content/consent/html`:** the default consent UI and legal footer
  as framework-neutral HTML; `/consent/astro` re-exports it (#53).

## Release gates and rollout

The required PR checks and the retained paired validation workflow must pass.
Publish only from the successful CI record, as in [releasing](../releasing.md).
A Site served through its own reverse proxy (nomia-bnq's
`bioeconomia.apambiente.pt`) passes the proxy's addresses as `trustedProxies`
once its blueprint wiring lands.
