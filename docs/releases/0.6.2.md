# 0.6.2: Standard published post listings

Prepare `@getquick/content` and `getquick/gq-content` together from one retained
`v0.6.2` candidate. The prior stable pair is 0.6.1. This release contains
[PR #65](https://github.com/Quick-Release/gq-content/pull/65), merged as
`d5f3b02f151b616c411aa978e862c532c52db5d8`. GQ Design stays at 0.10.4;
no SQL migration or CMS behavior change is introduced.

`runtime.listPosts({ page?, perPage?, language? })` lists standard published
WordPress posts and their total from the publication store alone. It returns
`found` with a paginated result or `unavailable`; unknown readiness cannot be
interpreted as zero. Existing publication eligibility and withdrawal protections
apply. The additive optional `postType` field distinguishes standard posts and
pages. Legacy entries still serve but must be refreshed or reread through
reconciliation before listing can confirm an empty result.

## Release gates and rollout

This document prepares a candidate; it does not declare publication complete.
Follow [the stable release policy](../releasing.md): owner review, successful
retained paired CI validation, separate publication authorization, then publication
of the exact CI bundle. Verify matching immutable npm and Composer artifacts;
partial publication blocks Blueprint adoption. Retain the manifest's source commit,
SHA-256 digests and npm SHA-512 integrity with the successful validation record.
A matching nightly is not a stable substitute.

The Blueprint owns managed pair pins. Nomia must adopt the resulting stable pair
through that mechanism, refresh legacy stored entries, verify complete initial
population and readiness, then deploy its prepared Notícias rendering. Render
exactly `Brevemente disponível` only when `found.content.total === 0`;
positive totals show news without that text; unavailable uses the Site's
unavailable response. A page beyond the end is a pagination case, not no news.
See [the API and adoption guide](../../frontend/README.md#standard-wordpress-post-listing).
