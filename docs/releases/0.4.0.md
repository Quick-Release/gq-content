# 0.4.0: headless Gravity Forms

Release `@getquick/content` and `getquick/gq-content` together from one retained
`v0.4.0` candidate. The prior stable pair was 0.3.2. No publication-store or
consent migration is added.

This release ships gq-platform ADR 0009's headless Gravity Forms capability. It
is optional, and nothing changes for a Site that doesn't opt in.
[ADR 0008](../adr/0008-deliver-gravity-forms-descriptors-with-publications.md)
records how descriptors are delivered.

- **CMS:** `modules/forms.php`, dormant without Gravity Forms. With Gravity
  Forms active, it adds `getquickForms` to WPGraphQL content nodes, republishes
  every entry that references a form when the form changes, and adds
  `wp gq-forms status [--format=json]` (exit 1 while a referenced form has a
  diagnostic).
- **Runtime:** `createContentRuntime({ forms: true })` stores each entry's
  descriptors as `forms`, and `publishedForm(path, formId)` reads them back.
- **`@getquick/content/forms`:** descriptor types and parsing, submission
  validation, `formsReadiness`, and post/redirect/get outcome state
  (`readFormState`, `clearFormStateCookie`).
- **`@getquick/content/forms/astro`:** `renderGravityForm`, a plain HTML form
  that posts to `/gq/forms/<id>`.
- **`@getquick/content/forms/server`:** `createFormsServer`.
- **`@getquick/content/forms/testing`:** fixtures, a Gravity Forms REST
  stand-in and assertions.

Unsupported in this release, and reported by readiness: Gravity Forms' CAPTCHA,
file uploads, payment and pricing fields, page breaks, conditional logic,
login-only forms, radio "Other" choices and field types outside the supported
list.

## Release gates and rollout

The required PR checks and the retained paired validation workflow must pass.
That workflow adds the `forms-astro` proof: the packed package in an Astro
Cloudflare Worker, run in Chromium without JavaScript, with Turnstile verified
through Cloudflare's siteverify using its test keys. Publish only from the
successful CI record, as in [releasing](../releasing.md).

gq-site 0.24.0 pins this pair and adds the managed `/gq/forms/` route and
readiness checks. Sites adopt it through gq-site, not by hand.
